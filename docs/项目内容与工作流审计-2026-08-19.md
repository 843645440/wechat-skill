# 项目内容与工作流审计（2026-08-19）

## 结论

项目的确定性排版、草稿幂等和写作评分基础已经较完整，主要风险不在“缺功能”，而在
**同一能力存在多套互斥说明、质量检查可以被顺序绕过、状态前置条件没有由运行时强制**。
本轮优先收敛单一真相源和最终交付门禁，没有扩大到公开发布、自动选题或账号外部运营。

## 内容创作审核

### 已具备的优势

- 标题、开头、价值密度、竖屏可读性、留存和读者收益已有可量化评分，并有金标样例校准。
- brief 优先于结构池，能避免“为了套结构而换题”；历史/人物题材不会被强塞行动清单。
- 结构、开头、结尾、矛盾类型和篇幅带可轮换，能减少连续文章同质化。
- 摘要作为标题后的第二钩子已有重复检测，正文与分享卡角色区分清楚。

### 下一阶段建议

1. **建立真实表现回流，而不是继续加静态规则。** 当前评分只能预测可读性，无法证明打开率、
   完读率或关注转化。下一步应定义账号级、文章级最小数据表，人工导入微信后台的曝光、阅读、
   完读、分享、关注与取关，再按内容支柱和结构复盘。
2. **把“事实质量”和“文风质量”分开观察。** 当前 scorer 擅长节奏与信息密度，不验证事实。
   不建议恢复机械 `sources.md` 硬门禁；更适合在需要联网核验的任务中保留可追溯依据，并在草稿
   人工审核时重点核对数字、时间和归因。
3. **评估账号 A 的人物志特例是否应独立成模式。** 它与通用“标题前三候选 + 刺点前置”规则
   存在合理例外，长期塞在 `writer_instructions` 会越来越难维护；真实样本足够后再拆专项 reference。
4. **不要把历史运营方案中的目标值当成行业标准。** 30% 打开率、50% 完读率等目标缺少当前
   账号基线与口径，应由后台真实分位数和连续 4—8 周趋势校准。

## 工作流编排审核

当前权威链路为：

```text
init → user-brief → topic → shape → begin → write/check → humanize
→ illustrations → cover → prepare(final QA) → finish(final QA + draft)
```

恢复原则保持不变：同一 `run_id` 成功结果复用；`draft/add` 已发出但结果不确定时禁止自动重发；
请求前或明确拒绝类失败可修复后重跑 `finish`。正文图可降级为 0 张，封面必须生成或使用账号
默认素材。流水线只写草稿箱，不公开发布。

## 暂不实施

- 自动开启热点、自动挑题、自动公开发布：超出默认授权边界，也会削弱 brief 驱动定位。
- 视觉审图循环：成本高、可重复性差，当前由确定性机械校验加草稿箱人工核对承担。
- 为每篇文章新增 renderer、source 文件或质量脚本：会重新制造多套真相源。
- 未接入真实后台数据前承诺阅读量或粉丝增长目标：缺乏可验证依据。
