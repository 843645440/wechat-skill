## 二、本轮新发现的问题

### P1-新1：测试套件 7 个 ERROR，全部是 WorkBuddy 沙箱 shim 的 bug（非流水线问题）

`python3 -m unittest discover -s tests` 277 个测试中 7 个 ERROR
（test_pipeline_job ×3、test_pipeline_simplification ×2、test_html_cover ×2）。
逐个核对 traceback 后锤实根因：

- 报错均为 `PermissionError: EEXIST: file already exists, mkdir .../T/tmp_xxx/config`
- 抛错点在 `sitecustomize.py` 的 `_brokered_path_mkdir`（WorkBuddy 注入的文件操作 shim）
- 复现实验：`pathlib.Path.mkdir(exist_ok=True)` **目录已存在时二次调用 → PermissionError**；
  对照组 `os.makedirs(exist_ok=True)` 二次调用 → 正常。
  即 shim 只劫持 pathlib.Path.mkdir，且未实现 exist_ok=True 语义

测试代码写法（`tests/test_pipeline_job.py:22` 的 `(root/"config").mkdir(exist_ok=True)`）
是标准 Python 语义，**没有错**。在无 shim 的环境（CI、普通终端）应当全绿。

**建议**：① 向 WorkBuddy 平台反馈 shim bug；② 若长期在本环境开发，可把测试里的
`Path.mkdir(exist_ok=True)` 统一替换为 `os.makedirs(..., exist_ok=True)` 绕过（一行语义等价）。

### P2-新2：begin 的 brief 校验报错信息与参考文档脱节

首次 begin 失败：`user-brief.md 的「## 思路」为空或过短`。但
`references/user-brief.md` 的模板说明里没有强调「## 思路」是**必需小节**，
我是靠报错回猜补上的。建议在 user-brief.md 参考文档开头加一行

### P2-新3：标题主体识别正则仍漏中文实体

「美联储本周加息概率86.5%，特朗普拦不住」被判「找不到可指认的主体」——
标题里明明有「美联储」「特朗普」两个实体。工具自己也提示"这条正则会漏判纯中文技术名词，
人工核一下"。已知限制、有兜底提示，可接受；若要修，给词表加官职/机构常见词即可。

## 三、测试方法教训（我自己的坑，记录防再犯）

1. **验证必须走真实代码路径**：第一版模拟复刻了旧公式（全量池哈希），得出"25.09% 依旧"的错误结论——
   实际新代码先过滤再哈希，概率恒为 0。
2. **函数靠 print 输出时，测试要读 stdout 缓冲**：`cmd_choose_theme` 返回 None、结果打在 stdout，
   前两版收集了返回值导致 hits 全是 None。
3. **固定行为要先清状态**：真实 job 的 format.details.theme 已固定，直接测会 100% 返回旧主题
   （这本身验证了"同 run 不换皮"的设计，但要测轮换必须先清掉）。
