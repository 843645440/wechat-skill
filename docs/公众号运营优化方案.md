## 二、内容质量提升方案

### 2.1 强制执行体检门禁（立即生效）

**问题**：batch-5 有 4 篇文章低于 75 分合格线却仍然进入了草稿箱。

**措施**：
1. 每篇文章写完后**必须**运行 `score_draft.py --article <article.md> --markdown`
2. **score >= 75 且 blocking_count = 0** 才允许进入 humanize 阶段
3. 不达标的文章按 `problems` 列表逐条修改，改完重跑
4. 这不是建议——这是流水线的硬门禁，batch-5 的问题在于门禁被跳过了

### 2.2 标题优化（提升打开率的核心）

batch-5 的标题存在明显问题——刺点靠后、缺乏数字、读起来像新闻通报。

**标题三原则**：
1. **刺点必须在 前 16 字**：信息流里读者只看得到前半截
2. **先满足「谁+干了什么」**：说不出主体读者就不会点
3. **损失框架 > 收益框架**：「别再花冤枉钱」比「教你省钱」更容易被点开

**标题改写示例**：

| 原标题 | 问题 | 优化方向 |
| --- | --- | --- |
| 英特尔把Gemini引入芯片研发，工程师先面对责任重分配 | 刺点在第 108 字才出现，通报体 | 「英特尔工程师开始给AI签字，出事算谁的」 |
| NotebookLM更名，Google让研究工具直接运行代码 | 主体不明确，读者不知道影响谁 | 「Google改名NotebookLM，研究者的核验成本翻倍了」 |
| Google给AI广告加制作标签，广告主的低成本创意开始留痕 | 28字太长，前16字无数字/断言 | 「AI广告要标来源了，低成本创意的痕迹藏不住」 |

**操作**：写正文之前先出 3 个不同刺点的候选标题，用 `score_draft.py --titles` 排序，30 秒就能选出最强标题。

### 2.3 结构轮换（提升完读率）

batch-5 的 5 篇文章结构高度同质——都是「事件背景→技术分析→影响展望」的变体，这正是写作检查清单里明确标注的**废结构**。

**六种可用结构**（来自 `structure-playbook.md`）：

| 结构 | 适合题材 | 优势 |
| --- | --- | --- |
| 冷开场倒叙 | 有具体事件/冲突 | 开头零铺垫，完读率最稳 |
| 反常识拆解 | 选型/工具/行业通稿反面 | 认知缺口天然抓人 |
| 代价追踪 | 效率工具/自动化/组织变革 | 代入感极强 |
| 时间线复盘 | 历史事件/人物/事故 | 结构自带钩子 |
| 判断清单 | 选型/避坑/上手指南 | 收藏率最高 |
| 对照实验 | 工作流改造/工具替换 | 数字天然是价值锚 |

**操作**：流水线已有 `shape --auto` 结构轮换机制（同 run_id 稳定、永不死锁），确保每篇都用它，不要手动跳过。

### 2.4 batch-5 四篇低分文章的共性问题清单

以下是体检脚本对 batch-5 低分文章反复指出的问题，需要在后续写作中重点避免：

1. **全文无加粗**——扫读的人抓不到任何东西。每段挑 1-3 个关键短语加粗，加粗的必须是判断和结论
2. **长句占比过高**（20% 超过 50 字）——中文口语的节奏是短句推进，反过来就变成公文
3. **连续 500+ 字无钩子**——读者在平铺的第三屏退出。每 500 字至少一个转折/悬念/提问
4. **利他物只有一种**——读者拿走的东西太薄。至少两种形态：判断标准 + 可执行步骤，或清单 + 可转述结论
5. **结尾空转**——必须有落点：判断标准/适用边界/可执行步骤/可转述结论，四选一或多选
6. **全文无问句**——读者始终是旁观者。至少一个把读者拉进来的问题

### 2.5 内容支柱策略

**账号 A「熵增时刻」——4 根内容支柱**：

| 支柱 | 占比 | 内容形态 | 示例 |
| --- | --- | --- | --- |

| 行业事件拆解 | 25% | 代价追踪 / 冷开场 | 「AI短剧播放破2亿，横店13万群演抢800个通告」 |
| 职业变化观察 | 25% | 时间线复盘 / 反常识 | 「AI替代的不是岗位，是岗位里那个不做判断的人」 |
| 选型避坑指南 | 20% | 判断清单 | 「5款AI编程助手横评：什么团队该用什么」 |

**账号 B「思想的野路子丶」——4 根内容支柱**：

| 支柱 | 占比 | 内容形态 | 示例 |
| --- | --- | --- | --- |
| 民生服务办事 | 30% | 判断清单 / 可执行步骤 | 「异地就医备案手机3分钟办完，但这2个选项别选错」 |

### 2.6 60/30/10 内容比例

遵循行业最佳实践的内容配比：

- **60% 价值内容**：教程、拆解、清单、科普——读者能带走东西
- **30% 互动内容**：提问、投票、话题讨论——把读者从旁观者变参与者
- **10% 推广内容**：产品/服务/活动——转化但不刷屏

## 三、粉丝活跃度提升方案

### 3.1 P0：开启评论功能（立即执行）

**现状**：两个账号的 `need_open_comment: 0`，粉丝完全无法互动。

**措施**：在 `wechat-accounts.json` 中将两个账号的评论配置改为：
```json
"need_open_comment": 1,
"only_fans_can_comment": 0
```

**配套**：
- 每篇文章结尾设置一个**互动问题**（不是「你怎么看」，而是具体的二选一或场景提问）
- 前 100 篇文章的评论务必**人工回复**，让粉丝感受到「这个号有人在看」
- 精选优质评论置顶，形成社区氛围

### 3.2 P0：启动账号 B（1 周内）

**现状**：账号 B「思想的野路子丶」零内容，完全闲置。

**措施**：
1. 用现有流水线为账号 B 生成首批 3 篇文章（按内容支柱分布）
2. 第一篇选择**高共鸣民生话题**（如就业/医疗/养老），用冷开场倒叙结构
3. 确保首篇体检分数 >= 85（比合格线高 10 分），给新关注者留下好印象

### 3.3 P1：配置自动回复系统

**关注后欢迎语**（两个账号各一套）：

账号 A：
> 欢迎来到熵增时刻。这里不写通稿，只拆机制。
> 回复【工具】获取 AI 工具选型清单
> 回复【职业】查看职业变化系列文章
> 回复【最新】获取本周推荐文章

账号 B：
> 欢迎来到思想的野路子。
> 这里写普通人的日子——好在哪、卡在哪、怎么办。
> 回复【办事】查看民生办事指南
> 回复【政策】查看政策落地追踪
> 回复【最新】获取本周推荐文章

**关键词自动回复**（首批）：

| 关键词 | 回复内容 | 账号 |
| --- | --- | --- |

### 3.4 P1：菜单架构设计

**账号 A 菜单**：
```
左：最新文章 → 最近 3 篇推送
中：内容分类 → AI工具 / 职业变化 / 行业拆解 / 选型指南
右：关于我们 → 公众号介绍 / 联系方式 / 投稿建议
```

**账号 B 菜单**：
```
左：最新文章 → 最近 3 篇推送
中：内容分类 → 民生办事 / 政策追踪 / 普通人故事 / 基建科普
右：关于我们 → 公众号介绍 / 联系方式 / 选题建议
```

### 3.5 P1：开启热点选题

**现状**：两个账号的 `topic_discovery.enabled` 均为 `false`，完全靠用户命题。

**措施**：将 `topic_discovery.enabled` 改为 `true`，但保持以下约束：
- `max_age_hours: 48`——只追 48 小时内的热点
- `require_story_kernel: true`——必须有故事内核，不写纯通报
- 人工审核：热点选题生成后由用户确认，不自动发布
- 频率控制：每周最多 2 篇热点文章，其余按内容支柱计划

**操作**：修改 `config/wechat-content-profiles.json` 中两个账号的 `topic_discovery.enabled` 字段。

### 3.6 P1：建立定时发布节奏

**目标发布频率**：每个账号每周 3 篇（周二/周四/周六）

**建议时间**：
- 账号 A：周二/周四 20:00，周六 10:00
- 账号 B：周二/周四 19:00，周六 9:00

**操作**：可创建定时自动化任务（automation），在指定时间触发流水线生成草稿。用户审核后手动发布。

### 3.7 互动内容设计

每篇文章结尾的互动设计（30% 互动内容的具体落地）：

| 类型 | 示例 | 频率 |
| --- | --- | --- |
| 二选一提问 | 「你觉得AI备课能替代教研组吗？A能 B不能，评论区说理由」 | 每周 1 篇 |
| 经验征集 | 「你用AI工具踩过最大的坑是什么？点赞最高的送选型清单」 | 每两周 1 篇 |
| 投票 | 「下期你想看哪个话题？1/2/3 投票」 | 每月 1 次 |
| 读者来信 | 选取粉丝留言展开成文，标注来源 | 每月 1-2 篇 |
