# 公众号写作 Skill：研究、交付与验证报告

**日期**：2026-07-27　**分支**：`slim-for-weak-models`　**交付物**：`.agents/skills/wechat-viral-writer/`

---

## 一、结论先说

做了一件事：**把「这篇文章有没有人读完」从主观判断变成可执行的分数。**

原因很直接——模型写完总觉得自己写得不错。这是它的系统性偏差，靠加提示词修不好。
所以新增的核心不是一份写作指南，而是一个**会打分、会指出第几行有问题、会给修法的脚本**，
并且把它挂进了流水线已有的 `check` 命令，模型跑不掉。

验证结果（同一把尺子）：

| 稿件 | 分数 | 说明 |
|---|---|---|
| 仓库里 5 篇旧的「新闻汇报腔」稿 | **61 / 63 / 64 / 65 / 76** | D—C，4 篇有阻塞项 |
| 新写的示例稿 `examples/gold-sample.md` | **95.8** | A |
| 按新 checklist 盲写的自测稿（第一版） | **94.0** | A，只卡字数 |
| 自测稿补足字数后（第二版） | **100.0** | A，零问题 |

**区分度是这套东西唯一的价值。**一个给所有稿子都打 90 分的体检脚本，比没有体检更糟——
它会让模型确信自己写得很好。

## 二、研究部分：抄到了什么

### 1. 2026 年分发机制的方向（第三方观测，非官方口径）

> ⚠️ 微信官方从不公布推荐权重。下面带百分比的数字全部来自第三方运营号的观测拆解
> （主要是柚子君营销《2026 公众号算法大变天》，交叉参考澎湃、壹伴等）。
> **方向可信，数字不可引用。**完整标注见 `references/distribution-2026.md`。

- **完读率成为第一权重指标（约 35%）**，超过打开率。有观测称读者点开后阅读进度
  不足 30% 就退出会被记为低质/标题欺诈信号。
- 分享转发约 30%、收藏约 20%、互动约 15%。
- **公域推荐占流量 70—90%**：读者大多不是粉丝，是陌生人 → 陌生主体必须先解释。
- **搜一搜带来近 40% 的新增关注** → 标题和小标题要用读者真的会搜的具体词。
- 导流限流是明确的平台规则（内容导流 / 互动导流 / 多重嵌套导流）。

**这一条改变了写作目标本身**：从「把事情说清楚」变成「让人一路滑不下去」。
标题党的算盘也被推翻了——高打开 + 低完读是负分组合，比低打开还糟。

### 2. 标题与开头

- 前 **16 个汉字**是所有场景都完整露出的部分，刺点必须前置。
- 四类有效刺点：数字锚定 / 反差结构（不是 A 而是 B）/ 否定断言 / 对号入座。
- **损失框架 > 收益框架**：「别再花冤枉钱」＞「教你省钱」。
- 开头 150 字内必须出现第一个具体信息。套话开场（「在当今」「随着…的发展」）
  是把最贵的三秒直接扔掉。

### 3. 大 V 拆解：三个人风格完全不同，共性只有四条

看了半佛仙人（热点+强观点+网络口语）、刘润（极短段落+可命名的概念）、
caoz（真实经验密度，不做运营动作也能缓慢稳定涨粉）。

抽出来能复用的是共性，不是风格：

1. **有稳定的「视角」，不是稳定的「腔调」**——模仿语气没用，要固定从哪个角度切入。
2. **有明确立场，从不骑墙**——「辩证地看」是没有观点的人的挡箭牌。
   没有立场的文章不会被转发，因为读者转发是为了表达自己的立场。
3. **解释机制，不描述现象**——新闻说发生了什么，大 V 说为什么会这样。这个差值就是订阅的理由。
4. **不装**——不知道就说不知道，主动暴露局限是建立信任最快的方式。

### 4. 涨粉的真实链路

```
有人读完 → 觉得某句话值得转述 → 转发 → 好友因为「是他转的」而点开 → 读完 → 关注
```

**关注发生在读完之后，不是点开之后。**所以「利他性」和「分享率」不是两件事：
读者转发不了一种情绪，他转发的是那句可以被复述的话。

### 四个维度怎么打分

| 维度 | 分 | 量化指标 |
|---|---|---|
| 开头/标题 | 20 | 标题 ≤32 字、前 16 字有刺点、150 字内进正题、无套话开场 |
| **信息量** | 25 | 最长无锚区间 ≤300 字、注水词 ≤4/千字、相邻段落重复度 <55% |
| **利他性** | 20 | ≥2 种利他物、结尾四分之一有落点、有加粗抓手 |
| **可读性** | 20 | 段落 ≤180 字、长句 ≤20%、每 800 字一个小标题、每段 1—3 处加粗 |
| 抓人 | 15 | 最长无钩区间 ≤500 字、有问句、结尾回扣开头 |

「价值锚」认七类：数字、年份、对比、因果、可搜索的外文专名、可核实的信源、
作者主动标记的重点（小标题/加粗）。**每条问题都带行号和修法**，不是只说「不够好」。

### 标题排序（写正文之前用，30 秒）

标题是整条漏斗最窄的一道闸门，所以它有独立的模式：

```bash
python3 <SKILL>/scripts/score_draft.py --markdown --titles "候选A" "候选B" "候选C"
```

它给每个候选打分并说明理由，实测（拿仓库自己的旧标题验证）：

```
✅ 100.0 · 15 字 · 别急着上多智能体，先算这三笔账          刺点：否定断言
   100.0 · 19 字 · 写了 2000 字没人读完，问题真不在文笔     刺点：数字
    50.0 · 28 字 · 英特尔把Gemini引入芯片研发，工程师先…    通报体，没有刺点
    45.0 · 12 字 · 关于公众号写作的几点思考                 周报腔
```

还有一条容易被忽略的提醒：**三个候选如果用的是同一类刺点，等于只想出了一个标题**，
脚本会直接说出来并建议换框架（收益 → 损失）。

### 摘要（digest.txt）也进了检查

分享卡上标题和摘要是并排出现的，**说同一句话等于只说了一句**。
`check` 现在会用字符 n-gram 判断摘要是不是在复述标题，太短（<12 字）也会提醒。

### 关键设计决定：挂进 `check`，而不是另开一条命令

`pipeline_runtime.py check` 现在会自动跑体检：

```json
"writing": {"score": 86.8, "grade": "B", "pass_line": 75,
            "dimensions": {"hook": 20, "value_density": 25, "reader_benefit": 15,
                           "readability": 17.8, "retention": 9},
            "report_command": "python3 …/score_draft.py --article … --markdown"}
```

- high 级问题并进 `problems`（前缀 `[写作·xxx]`），`score < 75` 也会拦。
- **软依赖**：Skill 不在时 `check` 照常工作，只是少一段反馈。
- 理由：模型已经会跑 `check`，多一条命令就多一个会被忘掉的步骤。
  这是「低成本人工干预」的关键——你不需要记得提醒它。

## 四、热点开关

**默认关闭。**开关在 `config/writer-config.json` → `hot_topic_radar.enabled`。

```bash
python3 <SKILL>/scripts/hot_radar.py --markdown          # 关着时告诉你怎么开，不联网
python3 <SKILL>/scripts/hot_radar.py --force --markdown  # 试一次，不改配置
```

**为什么默认关**：自动扫热点把「写什么」的决定权从人手里拿走了。这个决定关系到
账号的调性和长期定位，不该由一个脚本在后台悄悄做掉。

**实跑结果**（2026-07-27 凌晨，8 个源全部可用，210 条，聚类后出候选）：

```
72.4 [微博热搜,百度热搜] 长鑫上市 合肥能赚多少        ← 跨榜 = 真热
71.1 [微博热搜]          不要长期向AI倾泻心事
67.3 [百度热搜]          AI冲击短剧行业 "戏王"也扛不住了
```

数据源：微博热搜、百度热搜、头条热榜、36 氪、少数派、IT 之家、V2EX、HackerNews。
知乎热榜需要登录 Cookie，**默认关闭**（想用就自己补 headers，别把 Cookie 提交进 git）。
**不需要任何 API key。**

调试中发现并修掉的三个问题：

1. 微博接口没有 `Referer` 会 403 → 数据源支持自定义 headers（配置里已写好）。
2. RSS 是按时间倒序发的，拿「第几条」当热度用会让高频更新的科技站永远霸榜
   → RSS 类来源不计排名。
3. 一个站霸屏 → 加了 `max_per_source` 限额（跨榜条目不受限）。

**它不做的事**：不自动选题、不自动写 brief、不自动开流水线。它只把「今天有什么」
摆到桌面上。⚠️ **不要把榜单标题原样当选题**——榜单标题是新闻标签，你的选题是判断。

## 五、验证

```
221 个离线测试全部通过（新增 60 个）
5 个 Skill 元数据校验通过（新 Skill 已加进 CI）
组件库 lint：5/5 干净，0 error 0 warn
```

新增测试锁的不是「能跑通」，而是四件容易退化的事：

1. **区分度**：满分样例必须过线，「新闻汇报腔」必须被拦下，两者差距 >25 分。
2. **不误伤**：清单里的多个加粗、结尾在倒数第三段回扣开头——这些是好写法，
   早期版本两条都误伤过，现在各有一条测试钉住。
3. **开关是真的开关**：雷达在配置关闭时必须一次网络请求都不发（用 mock 断言）。
4. **降级**：单个榜单失败不能拖垮整轮，退出码恒为 0。

### 真实命令链跑过一遍（不是只跑单测）

在一个临时工作区里跑了 `init → topic → shape → begin → check`：

- `begin` 的 `writing_contract` 确实带出了 `readability_gates`（8 项）和 `length_plan`。
- 放进一篇好稿：`status: ok`，`writing.score = 100.0 (A)`，`problems: []`。
- 换成一篇「新闻汇报腔」：`status: fail`，`score 41.0 (E)`，**5 条阻塞项**，
  每条都带行号和修法：

  ```
  ✗ [写作·hook]           第 3 行：前 150 字里没有任何具体信息，全是铺垫
  ✗ [写作·value_density]  第 3 行：连续 1665 字没有具体信息（阈值 300 字）
  ✗ [写作·reader_benefit] 第 3 行：全文没有任何读者可以带走的东西
  ✗ [写作·readability]    第 3 行：有 1 个段落超过 260 字（最长 1665 字）
  ✗ [写作·retention]      第 3 行：连续 1665 字平铺直叙，没有转折/悬念/提问
  ```

  摘要复述标题、摘要过短也同时被点名。

### 自测循环发现的真问题

按新 checklist 盲写一篇稿，**第一版 94 分但卡在字数 1177 < 1500**。
这说明 checklist 漏了篇幅规划。已修：加了一条可以直接套的公式

```
开头 150 字 + 小节 N × 250 字 + 结尾 150 字 ≥ 1500  →  N 至少 5 个，稳妥 6—8 个
```

补完之后第二版 **100 分，零问题**。

## 六、你明天怎么用（三种情况）

**情况 1：你有主题（默认路径，什么都不用改）**

照旧跑流水线。变化有两处，都不需要你操作：

- `begin` 输出的 `writing_contract` 里多了 `readability_gates` 和 `length_plan`
  ——体检的判据在**动笔之前**就交给模型了，不用等写完再返工。
- `check` 会多给一段写作反馈，模型自己修到过线。

**情况 2：你不知道写什么**

```bash
python3 .agents/skills/wechat-viral-writer/scripts/hot_radar.py --force --markdown
```

看清单 → 选一条 → **用你自己的话说出你的判断**（这一句就是 brief 的核）→ 跑流水线。

要长期开着就把 `config/writer-config.json` 里 `hot_topic_radar.enabled` 改成 `true`。

**情况 3：某篇稿子你觉得不对劲，但说不出哪里不对**

```bash
python3 .agents/skills/wechat-viral-writer/scripts/score_draft.py --article <稿子> --markdown
```

它会告诉你第几行有问题、扣了多少分、怎么改。

## 七、还能继续优化的地方（诚实清单）

按价值排序，都不是阻塞项：

1. **阈值是拍的，不是测的。**300 字无锚区间、500 字无钩区间这些数字来自公开经验和
   本仓库样本的区分度，**没有跟真实的完读率数据对过**。等公众号后台攒够数据，
   可以用「实际完读率 vs 体检分数」回归一次，把阈值调准。这是最有价值的下一步。
2. **反刷分能力有限。**目前靠 SKILL.md 的硬规则约束，脚本层面拦不住「堆假数字」。
   可以加一个「数字是否带单位和上下文」的检查，但误伤风险不低。
3. **知乎热榜要 Cookie。**目前默认关。如果你愿意手工贴一次 Cookie，能多一个高质量源。
4. **利他物识别靠词表。**「判断标准」这类表达如果换个说法（比如纯粹用排比句给标准），
   可能识别不出来。词表可以继续加，但边际收益递减。
5. **没有跨篇去重。**同一个观点连写三篇，体检不会察觉。流水线已有的
   `structure-rotation` 只管结构不管观点。
