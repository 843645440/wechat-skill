# 用户 Brief（命题生产入口）

流水线默认只接受**用户给出的主题 + 思路**，不自动选题。唯一例外是用户明确开启的
`wechat-public-event-archive`：它必须先完成官方信源核验，再提供等价的完整 brief。

## 最低完备性

| 字段 | 必填 | 说明 |
|------|------|------|
| 主题 | 是 | 一句话；可直接作工作标题，成稿标题可润色但 ≤32 字且不改核心 |
| 思路 | 是 | 论点、时间线、大纲、要点、素材摘录任一即可；须有可展开内容 |
| 账号 | 是 | `a` / `b` 等档案别名 |
| 必须写到 | 否 | 事实、结论、段落，成稿不得删 |
| 禁止写到 | 否 | 如「不要防骗清单」「不要我站哪边」 |
| 结尾偏好 | 否 | 影响收束 / 人物结局 / 开放问题 / 用户指定句 |
| 配图 | 否 | 封面路径、正文图路径与插入位置说明 |
| 情绪/读者 | 否 | 覆盖账号默认 voice 时使用 |

## 推荐落盘 `user-brief.md`

```markdown
# Brief

## 主题
……

## 思路
- ……
- ……

## 必须保留
- ……

## 不要写
- 不要写成普通人防骗手册
- 不要单独开「我站哪边」

## 结尾
以当事人结局 / 行业影响收束（择一或组合）

## 配图
- 封面：…
- 正文：…
```

## Agent 行为

1. **缺主题或思路过空** → 追问，不联网找题。  
2. **思路与事实以 brief 为准** → 可润色、补背景解释，不得换事件、不得反转用户明确结论。  
3. **用户给了时间线** → 按时间线组织，勿打乱成无关结构秀。  
4. **用户禁止的段落类型** → 硬遵守（高于账号默认「清单/站队」习惯）。  
5. **用户给了图** → 优先用户图；不要用 AI 图覆盖，除非用户要求重做。  
6. **与近文主题撞车** → 提示用户，不擅自改题。

## 公共事件档案上游

自动档案 brief 必须同时存在 `source-dossier.json`，并额外写明：生效裁判或官方结论状态、
来源 ID、时间线、隐私边界、克制正式的写作口径、正文不配图。它不是 `auto-hotspot`，不得用
48 小时热度或商业媒体摘要代替官方材料。没有合格题材时跳过，不生成空 brief。

## 从 brief 提炼 job 字段

写入 `topic` 时 `--source provided`：

- `event_focus` ← 主题或思路首句  
- `hook` / `tension` / `reader_stakes` ← 有则摘，无则弱补全或留空  

不要为了填满字段编造 brief 没有的「读者代价」。

## 反模式

- 无 brief 扫 Trending / 48h 热点顶上  
- 把历史复盘改成「今晚你能做的五件事」  
- 法律结论已清仍单开「我站哪边」  
- 用户要「人物结局结尾」却写成行动号召 CTA
