# 热点雷达：一个默认关闭的开关

## 开关在哪

```
.agents/skills/wechat-viral-writer/config/writer-config.json
└── hot_topic_radar.enabled     ← 默认 false
```

```bash
<SKILL> = .agents/skills/wechat-viral-writer

# 关着的时候跑：会告诉你怎么开，不会去联网
python3 <SKILL>/scripts/hot_radar.py --markdown

# 只试一次（不改配置，下次仍然是关的）
python3 <SKILL>/scripts/hot_radar.py --force --markdown

# 永久打开：把 config/writer-config.json 里 enabled 改成 true
```

## 为什么默认关

本仓库的默认模式是**用户命题**：用户给主题和思路，流水线负责写。

自动扫热点是另一种模式，它把「写什么」的决定权从人手里拿走了。这个决定
关系到账号的调性、立场和长期定位，**不该由一个脚本在后台悄悄做掉**。

所以它是一个开关，而且默认是关的。打开它是用户的一次明确动作。

## 它做什么、不做什么

**做**：
- 并发拉取 8 个公开榜单（微博热搜、百度热搜、头条热榜、知乎热榜、
  36 氪、少数派、IT 之家、V2EX、HackerNews）
- 跨榜单聚类——同一件事在不同榜单叫法不同，合成一条
- 按「上榜数（40）+ 关键词命中（30）+ 榜内排名（30）」打分
- 输出候选清单，每条带三个可用的切入角

**不做**：
- ❌ 不自动选题
- ❌ 不自动写 `user-brief.md`
- ❌ 不自动启动流水线

它只把「今天有什么」摆到桌面上。**选哪条、怎么写，仍然是人的决定。**

## 正确用法（三步）

```bash
# 1. 看清单
python3 <SKILL>/scripts/hot_radar.py --markdown --top 8

# 2. 选一条，自己写 user-brief.md：
#    - 主题（一句话，不是榜单标题）
#    - 你自己的判断（这才是文章的核）
#    - 必须写到的点 / 禁止写的点

# 3. 走正常流水线
python3 <PIPELINE>/scripts/pipeline_job.py init --project-root <ROOT> --account a --topic "<你的主题>"
```

⚠️ **最重要的一条**：不要把榜单标题原样当选题。

```
榜单标题：长鑫上市 合肥能赚多少
❌ 直接当主题 → 写成一篇没有立场的财经复述
✅ 提炼成你的角度 → 「一家本地国资押注十年的芯片厂上市了，
                     真正被改变的是合肥的招聘市场」
```

**榜单标题是新闻标签，你的选题是判断。**中间那一步转换，是文章有没有价值的分界线。

## 输出怎么读

```
## 1. 长鑫上市 合肥能赚多少　`72.4`
- 上榜：微博热搜、百度热搜          ← 跨榜 = 真热，不是单站自嗨
- 理由：2 个榜单同时在说；最好排名第 3；命中关注词：上市
- 别名：长鑫科技员工回应上市         ← 同一件事的其他说法，帮你找角度
- 可选切入角：机制拆解 / 代价与责任 / 判断标准
```

- **跨榜数是最可信的信号**。只有一个榜单在说的，往往是那个平台的内部话题。
- **分数只用来排序，不是质量判断**。72 分不代表这条值得写。
- **三个切入角是模板，不是成稿**。选一个，然后想清楚你自己的判断是什么。

## 什么时候别用

1. **今天没有达到分数线的候选时**——脚本会直接说「今天没有值得写的」。
   这是一个结论，不是一个失败。**不要硬写。**
2. **热点属于排除清单里的类目时**——娱乐八卦、明星塌房、灾难伤亡、股票荐股、
   医疗偏方。配置里 `keywords_exclude` 已经挡掉大部分，但挡不住全部。
3. **你没有真实判断的时候**。热点写作最容易翻车的形态就是「跟着通稿复述一遍」，
   这正是本仓库要避免的「新闻汇报腔」。

## 配置怎么调

```jsonc
"hot_topic_radar": {
  "enabled": false,           // 总开关
  "top_n": 8,                 // 输出几条
  "min_score": 30,            // 分数线，低于这个不进清单
  "max_per_source": 3,        // 单一来源最多占几条，防止一个站霸屏
  "cluster_threshold": 0.45,  // 聚类相似度阈值，调高＝更严格
  "keywords_include": [...],  // 命中加 30 分，按账号定位改
  "keywords_exclude": [...],  // 命中直接丢弃，安全阀
  "sources": [...]            // 数据源，可加可关
}
```

**加一个新数据源不需要改代码**，在 `sources` 里加一条即可：

```jsonc
{
  "name": "某站",
  "enabled": true,
  "kind": "rss",              // json | rss | baidu
  "url": "https://example.com/feed",
  "limit": 20,
  "weight": 1.0,
  "headers": { "Referer": "https://example.com/" }   // 挑食的站点才需要
}
```

`kind: json` 还需要 `path`（点分路径，如 `data.realtime`）和
`title_field`（如 `word`、`target.title`）。

## 失败是常态，不是故障

榜单接口经常改版、限流、要 Cookie。脚本的设计是：

- **单个源失败不影响其他源**，错误写进 `failed_sources`
- **退出码恒为 0**，没有网络时得到的是一份空清单，不是一个崩溃
- 已知需要额外条件的源：
  - 微博热搜：必须带 `Referer: https://weibo.com/`（配置里已写好，不需要登录）
  - 知乎热榜：需要登录 Cookie，**默认关闭**。想用就自己在 `headers` 里补
    Cookie，**别把 Cookie 提交进 git**。

看到 `⚠️ 某某：网络失败` 是正常的。只要还有 4–5 个源可用，清单就有意义。
