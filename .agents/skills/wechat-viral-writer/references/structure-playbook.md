# 六种结构：别每篇都用「背景—分析—展望」

结构决定读者的行进路线。同一批事实，换一个结构，完读率能差一倍。

本仓库的 `wechat-content-pipeline` 已经有结构轮换机制（`shape --auto`），
避免连续几篇撞车。这里补的是**每种结构具体怎么写、什么题材适合**。

---

## 1. 冷开场倒叙（cold-open）

```
一个具体画面/动作 → 「为什么会这样」 → 展开机制 → 回到那个画面给结论
```

**适合**：有具体事件、有冲突点的题材。
**优势**：开头零铺垫，最贵的 3 秒直接给画面，完读率最稳。
**要点**：开头那个画面必须在结尾被重新提起。闭环是转发的理由。

> 昨天我把五篇已经发出去的旧稿，一篇一篇丢进体检脚本。

---

## 2. 反常识拆解（myth-busting）

```
读者默认相信的 A → 「但实际上不是」 → 拆机制说明为什么 → 给新的判断标准
```

**适合**：选型、工具、方法论、行业通稿的反面。
**优势**：认知缺口天然抓人；结论自带可转述性。
**要点**：A 必须是读者**真的**相信的东西。反一个没人信的稻草人，读者只会觉得你在自嗨。

> 贵一倍不等于更强。

---

## 3. 代价追踪（who-pays）

```
一个被宣传为好事的变化 → 「省下来的成本去哪了」 → 追到具体的人和岗位 → 谁签字谁担责
```

**适合**：效率工具、自动化、组织变革、政策落地。
**优势**：把抽象的「效率提升」翻译成读者自己的处境，代入感极强。
**要点**：情绪必须钉在**可核验的机制**上——权限、验收、工时、预算、签字，
不是钉在形容词上。

---

## 4. 时间线复盘（timeline）

```
起点 → 关键节点 1、2、3（每个节点一个小标题）→ 结局 → 一句判断
```

**适合**：历史事件、人物、公司兴衰、事故复盘。
**优势**：结构自带钩子（读者想知道后来怎么了）；小标题天然是结论句。
**要点**：**事实线清晰 + 结局说明白，本身就是完整的利他物**，
不要硬塞「普通人怎么防」。

---

## 5. 判断清单（decision-list）

```
问题场景 → 判断维度 1/2/3（各一个小标题）→ 什么情况选 A、什么情况选 B → 边界
```

**适合**：选型、避坑、上手指南。
**优势**：收藏率最高的一种形态；读者知道内容有边界，愿意读完。
**要点**：每一项必须给**可执行的判据**，不是「要综合考虑」。清单项 3–5 条最佳，
超过 7 条读者记不住。

---

## 6. 对照实验（before-after）

```
改之前的具体状态（含数字）→ 改了什么 → 改之后的具体状态 → 哪些没改善
```

**适合**：工作流改造、工具替换、流程优化。
**优势**：数字天然是价值锚，信息量维度基本满分。
**要点**：**必须写「哪些没改善」**。只报喜的对照实验读起来像软文，
主动说出没解决的部分反而建立可信度。

---

## 选结构的三个问题

1. **有没有一个具体画面能当开场？** → 有，用 1
2. **读者脑子里有没有一个错误的默认答案？** → 有，用 2
3. **这件事的成本落在谁头上？** → 说得清，用 3

其余按题材：历史/人物 → 4，工具/选型 → 5，改造/迁移 → 6。

## 反面：为什么「背景—分析—展望」是废结构

```
❌ 一、事件背景  二、深层原因  三、影响分析  四、未来展望
```

三个问题：

1. **背景在最前面**，把最贵的位置给了读者最不关心的东西。
2. **小标题全是目录词**，扫读的人拿不到任何信息。
3. **「未来展望」必然空转**，因为作者也不知道，只能写「让我们拭目以待」。

这个结构的唯一优点是好写。它同时也是完读率最低的结构。
