# 可读性：竖屏手机上的节奏

先接受一个不太舒服的前提：**手机上没有「读者」，只有「扫描仪」。**

一个人在地铁上点开你的文章，拇指是往上推的。他不是在逐字理解，他是在快速判断
「这玩意儿值不值得我停下来」。所有排版规则都是从这个事实推出来的。

## 段落：60–150 字

体检脚本的阈值：超过 **180 字**算长段，超过 **260 字**判 high。

原因很物理：一屏手机大约放 200–300 字。**一个 260 字的段落，就是一整屏没有任何
呼吸口的黑字。**读者在这里退出，和内容好坏无关。

```
❌ 一段讲三件事，180 字连着推
✅ 一段一件事，讲完就空行
```

拆段的判据不是字数，是**语义**：一段只讲一件事。讲完了就换行，哪怕只有 12 个字。

短段落还有个副作用：**它逼你把话说利落。**一件事只有 60 字的位置，你会自动删掉
那些「可以说是」「在一定程度上」。

## 句子：平均 25 字，长句占比 <20%

体检脚本把超过 50 字的句子算长句，占比超过 20% 扣分。

中文口语的节奏是**短句推进，偶尔一个长句作缓冲**。反过来就变成公文：

```
❌ 由于该功能在实际部署过程中需要考虑权限配置、数据隔离以及审计合规等多个维度的
   要求，因此团队在推进过程中往往会遇到超出预期的阻力。（62 字）

✅ 这个功能在实际部署时要过三关：权限、数据隔离、审计。
   每一关都比想象中慢。（两句，24 + 11 字）
```

改写手法：**把「由于…因此…」拆成两句，把并列成分变成冒号后的短清单。**

## 小标题：每 500–800 字一个

小标题是给**扫读者**看的。一个人快速下滑，只有小标题会进入他的视野。

所以小标题的写法只有一条规则：**它本身要是一句结论，能被单独读懂。**

```
❌ 背景介绍 / 现状分析 / 问题与挑战 / 总结与展望
❌ 二、技术层面的考量
✅ 每 300 字必须换一个新的具体信息
✅ 算力扩展并不等于研发周期同比缩短
✅ 回到那五篇 D 和 E
```

反面例子的共同点：它们是**目录词**，不是内容。读者扫过一排「背景 / 分析 / 展望」，
拿到的信息是零。

一个检验方法：**把全文的小标题单独抽出来排成一列，它们应该构成一个能读的提纲。**

## 加粗：每段 1–3 个

加粗的作用是给扫读的人留抓手。所以：

- **加粗的必须是判断和结论**，不是形容词，不是名词。
- 每段 1–3 个。超过 3 个＝全都加粗＝全都没加粗。
- 清单块例外：每个条目的引导词可以加粗。

```
❌ 这个功能**非常重要**，会带来**极大的**效率提升。
✅ 这个功能真正改变的是**谁来签字**，不是效率。
```

## 其他节奏工具

**清单**：三个以上的并列项一律改成清单。清单是完读率最高的内容形态之一——
读者知道它有边界，会愿意读完。

**一句话独立成段**：最重的那句话单独占一段。这是中文写作里最便宜的强调手段，
比任何加粗都有效。

> 删掉之后文章毫发无损的句子，就该删掉。

**空行**：微信排版会把连续段落挤在一起。段间必须留空行。

**图**：正文图不超过 3 张（流水线硬门禁）。图的作用是**给眼睛一个休息点**，
所以放在长节之间，不是放在开头凑气氛。

## 预计阅读时长

体检脚本按 400 字/分钟估算。一篇 3000 字的文章约 7.5 分钟。

这是个有用的自查数字：**超过 8 分钟的文章，完读率会明显掉。**如果内容确实需要
这个长度，就必须把钩子密度提上去（见 hook-and-title.md 的最长无钩区间）。

## 手机预览是最后一道检查

排版完成后，用手机看一遍，从头往下滑：

1. 遇到任何一整屏都是黑压压的字的地方——就地拆段。
2. 遇到任何你想快速划过去的地方——那里就是读者退出的地方，删或改。
3. 只看小标题划一遍——如果只看小标题也能大致知道文章讲了什么，就合格了。
